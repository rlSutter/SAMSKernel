# SAMS Kernel: routine reference

**Routes.** Every routine here is available to both routes: **[PC]** (a cartridge built with `skbuild.py`) and **[TI]** (a program assembled in the workbench); `MUPLAY` needs a song in SAMS pages, so it is **[PC]**. The assembly source is the same either way.

Generated by `tools/docindex.py` from the header comments in `kernel/`; the comments are canonical.
Registers listed as "Uses" are every register the routine can change, including through what it calls.
Routines marked *leaf* never call another routine and may be called with a bare `BL`.

## The loader (loader.a99)

### `START` *(internal)*

the cartridge's program: the four checks, then the copy.  Never returns: it ends by branching to the kernel, or in REFUSE.

### `CPBK` *(internal)*

copy the 8K bank selected by writing *R1 to R2. Position independent; uses R3, R4; never touches R11.

### `REFUSE` *(internal)*

show the message list at R1 in 40-column text and wait for FCTN = .  No stack and no expansion RAM are assumed (there may be no memory card at all): a leaf, using only registers, scratchpad and VRAM. Message list: BYTE row, then a length-prefixed line, centred; row >FF ends. A line of length 2 holding '>' '?' shows the failing page in hex.

### `RFHEX` *(internal)*

low nibble of R4 as a hex digit to the VDP.  Leaf (called from REFUSE, which keeps nothing in R11).

## Main loop and exit (kernel.a99)

### `KEXIT` *(internal)*

quit to the TI title by the console's own reset (BLWP @>0000), as FCTN-QUIT does.  From Lantern's RESTRT: the sound chip silenced, the keys let go (at most a second), every F18A register the kernel changed put back as at power-up (the console's reset sets only VR0-VR7), the memory card's mapping switched off (pages sit in their own windows, as the identity map had them, so this code runs on).

## VDP and the frame wait (vdp.a99)

### `VDPWR`

write a VDP register. R0 = >RRDD  where RR = >80 | register number, DD = data

### `VWAD`

set VRAM write address.  R0 = address (>0000->3FFF)

### `VRAD`

set VRAM read address.  R0 = address

### `VMBW`

block write.  R0 = VRAM address, R1 = source, R2 = byte count

### `VMBR`

block read.  R0 = VRAM address, R1 = dest, R2 = byte count

### `VFILL`

fill.  R0 = VRAM address, R1 = byte (high), R2 = count

### `VSBW`

single byte write.  R0 = VRAM address, R1 = byte (high)

### `VSYNC`

wait for the next vertical blank.  Interrupts are allowed in only here, long enough for the console ISR to tick its frame counter (and play any sound list); masked everywhere else.  The screen-blank timer is not cleared here but on each key (KPUT), so the console blanks the screen after nine idle minutes.  Adds 1 to FRAME.  Uses R0.

### `VSBR`

single byte read.  R0 = VRAM address; R1 = the byte (high byte).

## The F18A (f18a.a99)

### `F18UNL`

unlock the F18A extended registers, unless they are unlocked already.  An F18A stays unlocked through the console's reset (a Quit), and ANY write to VR57 while unlocked locks it again: an unlock sequence sent then locks it, the game falls back to plain colours and the title breaks. So first ask: select status register 1 and read the ID (twice: on a locked F18A or a 9918A the write lands on VR7 and the reads return status register 0, the first of which clears its flags).  Only if no F18A answers, write >1C to VR57 twice.  On a stock 9918A that lands on VR1 (blanking the screen), so F18UNL must be followed by a full register init (VDPINI).

### `F18PAL`

load palette entries. R0 = first palette index (0-63), R1 = table of words >0RGB, R2 = entry count VR47 = >C0 | index puts the data port into palette mode with auto-increment; each entry is two data-port writes (0R, GB).

### `F18OFF`

put back every F18A register the kernel (VMODE, VREG) can change, as at power-up, before the console's reset (which sets only VR0-VR7): no 30 rows, no enhanced colour, no position attributes, no second tile layer, no bitmap layer, no scroll, the stop-sprite register at its default, status register 0, and the sixteen standard colours.  Lantern learned this the hard way: the TI title is wrong otherwise.

## F18A detection (f18det.a99, loader only)

### `F18DET` *(internal)*

after F18UNL, select status register 1 and read the ID. Bits 7-5 = 111 identify an F18A, or an F18A-compatible PICO9918, whose ID is >E8 (bit 3, its emulation marker; bits 1-0 are live status, so masked off).  Returns R0 = 1 if found, else 0; VDPPIC = 1 for a PICO9918. Restores VR15 = 0 and VR7 (which a real 9918A would have hit).

### `F18RDV` *(internal)*

the firmware version from status register 14 (e.g. >19 for 1.9) into F18VER as a word.  Only after F18UNL found an F18A.

## Memory card detection (amsinit.a99, loader only)

### `AMSDET` *(internal)*

detect a mapper.  Must be called in pass-through mode (before AMSINI).  Returns R0 = 1 if present, 0 if not. Uses R1-R3, R12.

### `AMSINI` *(internal)*

identity-map all 16 windows and switch mapping mode on. After this, page n is at address n<<12 for n = 0..15, which means the kernel at >A000 is on pages >A->D and nothing moved. Uses R1-R3, R12.

### `CURINI` *(internal)*

record what the identity map put in each window (the tracking words live in slot A, so this runs after the loader has cleared it).

### `PAGEA` *(internal)*

map pages R0 and R0+1 into slot A (>2000, >3000).

### `AMSSIZ` *(internal)*

how many pages the card has: R0 = 32, 64, 128 ... up to 4096 (a 16M card).  Writes a marker to page >10 and checks whether a write to page >10+32, +64 ... +2048 lands on it (the card decodes only as many page bits as it has).  Run after AMSINI and before anything is loaded: it overwrites the first word of page >10 and of the pages tried.  Leaf apart from MAPPG (R11 kept in R6).  Uses R0-R6, R12.

### `AMSTST` *(internal)*

write a page-specific word to the first and last word of every page from >10 up to R0-1, then check them all.  Pages below >10 are skipped (slot A, the kernel's pages and slot B's default pair).  Run by the loader before loading: it is destructive.  Returns R0 = 0 if every page answered, else the first failing page.  R11 kept in R6; uses R0-R7, R12.

## SAMS paging (pager.a99)

### `PAGEC` *(internal)*

map pages R0 and R0+1 into slot C (>C000, >D000): a module. Recorded in CURCC/CURCD.  Kernel use only (see above).  Uses R0-R3, R7, R12.

### `MAPPG`

map one page into one window. R0 = page (0-4095), R1 = window (0-15) Uses R2, R3, R12.  Leaf.  Does not update the tracking words: use it for windows you track yourself; PAGEB, MAPE and MAPF track slot B. The register takes the page's low 8 bits in the even byte and bits 8-11 in the odd byte (a card of 1M or less ignores the odd byte): the page with its bytes swapped.

### `PAGEB`

map pages R0 and R0+1 into slot B (>E000, >F000), recorded in CURBE/CURBF.  Uses R0-R3, R7, R12.

### `MAPE`

map page R0 into window >E000 / >F000 alone, unless it is there already; recorded in CURBE / CURBF.  Leaves.  Use R1-R3, R12 (nothing, when the page is already mapped).

### `MAPF`

map page R0 into window >E000 / >F000 alone, unless it is there already; recorded in CURBE / CURBF.  Leaves.  Use R1-R3, R12 (nothing, when the page is already mapped).

### `GETPB`

the pages slot B holds now: R0 = the page in >E000, R1 = the page in >F000.  Save them to put slot B back later with SETPB.  Leaf.

### `SETPB`

put slot B back as it was: R0 = the page for >E000, R1 = the page for >F000 (what GETPB gave; the two pages need not be consecutive).  Uses R0-R4, R12.

## Text 80, colour schemes, the DMA row mover (video.a99)

### `LDSCHM`

load colour scheme SCHEME (0-4) into palette entries 0-15.  In an enhanced colour mode (tiles) entry 1 is then made the text colour (the scheme's entry 2), so that attribute 0 shows text on the page: with a one-plane pattern, pixel colour 1 is entry 1 and colour 0 entry 0. Maps the data bank into slot B and puts back what was there.  Uses R0-R4, R7, R12.

### `SETSCH`

make colour scheme R0 (0-4) the current one and load it.  The screen is not rewritten: every cell's attribute names roles, and the palette is what changed.  Uses R0-R4, R7, R12.

### `VREG`

write F18A register R0 (0-63) with the byte in the high half of R1. The F18A must be unlocked (the loader did it; VMODE keeps it so).  Uses R0, R1.  Leaf in effect (it tail-calls VDPWR).

### `VMODE`

set the display mode.  R0 = the base mode (VMT80 text 80, VMT40 text 40, VMGM1 graphics I, VMGM2 graphics II, VMMC multicolor), R1 = the options added together (VO30 30 rows, VOPOS an attribute per position, VOTE1-3 tile enhanced colour, VOSE1-3 sprite enhanced colour, VOSPR sprites on, VOS16 16 x 16 sprites, VOSMG magnified).  Sets every register the modes use (tile layer 2, the bitmap layer, scrolling and palette selects off), the VRAM tables to a blank screen in the colours of the current scheme, the glyph set in the pattern table of the text-like modes, and the text routines' variables (TXCOLS TXROWS TXCELLS TXATTR NAMBAS).  The display is off while it works.  The VRAM map is in kdefs.a99.  Not every combination exists: enhanced colour tiles apply to Text 80, Text 40 and Graphics I; Graphics II and Multicolor ignore VOPOS and VOTE1-3, and Graphics II has no 30-row form.  Uses R0-R9, R12 and what PAGEB uses; slot B is left as it was.

### `VMTAB` *(internal)*

the VRAM tables for the mode VMODE has just set up: blank screen, the font, the sprite attribute table cleared, the GPU program, the palette. Uses R0-R9.

### `VSHIFT`

move R2 rows of TXCOLS bytes in VRAM from R0 to R1 with the F18A's DMA engine, started by its GPU: R3 = 0 to copy forwards (from the first bytes), 2 backwards (from the last bytes; R0 and R1 then point at the last byte of each block), as overlapping moves need.  Waits until the GPU is idle again.  Uses R0-R4.

### `T80INI`

the boot mode: Text 80, 30 rows, an attribute per position (VMODE with VMDEF), and the F18A's DMA engine tested.  Called once by KSTART before the first module runs.  Uses what VMODE and DMATST use.

### `DMATST` *(internal)*

test the F18A's DMA engine once: 80 bytes of a pattern at VRAM >1500 are copied by VSHIFT to >1580 and read back.  NODMA = 0 if they arrived, else non-zero (an F18A whose firmware has no DMA: the application then redraws rows instead of moving them).  Uses R0-R4.

### `GPUPRG` *(internal)*

the GPU's program, copied to VRAM at GPUAD by T80INI: the mailbox's 8 bytes into the DMA registers (>8000->8007), then a write to >8008 starts the copy; IDLE until the next start.

## The keyboard (keys.a99)

### `KINIT`

the keyboard as at power-up: no chord down, nothing buffered. The kernel calls it once at boot.  Leaf.  Uses nothing.

### `KSCAN`

read the six keyboard columns into KEYMAP (0 bit = pressed; row r is bit r of a column's byte), then ALPHA LOCK into ALOCK. Output 21 is held high while scanning so ALPHA LOCK stays off input 7 (FCTN's row).  ALPHA LOCK is then read with column 0 selected and output 21 low; input 7 low means down, unless FCTN is held, whose key pulls the same line: then the last state is kept.  Leaf.  Uses R1-R4, R12.

### `KDECOD`

the chord in KEYMAP: R0 = its code in the high byte, or 0 for no key (or a chord with no code); R1 = modifier flags in the high byte (>80 FCTN, >40 SHIFT, >20 CTRL, >10 ALPHA LOCK).  The first key found, column by column, wins.  FCTN takes precedence over CTRL over SHIFT. ALPHA LOCK capitalises letters typed with no modifier.  Leaf.  Uses R0-R7.

### `KPOLL`

scan, decode, and buffer a code when a key goes down, and on each repeat while it is held.  A code comes from the key and the modifiers held as it went down; letting go of a modifier before the key (or pressing one late) changes nothing while that key stays down, so releasing CTRL a moment before B never types a stray 'b'.  Repeats send the key's first code.  Uses R0-R7, R12.

### `JOYPOLL` *(internal)*

read both joysticks (keyboard columns 6 and 7; the rows are fire, left, right, down, up, 0 = active) into JOY1 and JOY2 as JFIRE|JLEFT|JRIGHT| JDOWN|JUP (1 = active), noting presses in JOYN1 and JOYN2; and, if JOYKEY says so, type arrow-key and ENTER codes for them with the keyboard's repeat.  Uses R0-R6, R12.

### `JOYRD` *(internal)*

R1 = a column in the high byte (>0600 joystick 1, >0700 joystick 2), R5 = JOY1 or JOY2: the state word at R5 gets what is down now, and the presses that are new join the word four bytes on (JOYN1, JOYN2). Leaf. Uses R1-R6, R12.

### `JOYGET`

joystick R0 (1 or 2): R1 = what is down now (JFIRE|JLEFT|JRIGHT|JDOWN| JUP), R2 = what went down since the last JOYGET (cleared by this call), so a program sees every press however brief.  Any other R0: R1 = R2 = 0.  The state is read once a frame, by KPOLL, so it follows the main loop (and KIDLE). Leaf. Uses R1, R2.

### `KPUT`

put code R0 (high byte) in the buffer; dropped if it is full. A key restarts the console's screen-blank timer and turns the display back on, should the console have blanked it: VR1 = VR1CPY with the display bit set, so the current mode is kept (Text 80 in the editor, Graphics II on the title).  Leaf.  Uses R2, R3.

### `KEYGET`

the next code from the buffer: R0 (high byte), or 0.  Leaf. Uses R0, R2.

### `KFLUSH`

throw away every buffered code (a key held down will repeat again).  Leaf.  Uses nothing.

### `KIDLE`

poll the keyboard if a frame has passed (the VDP's frame flag), so keys typed during long work are buffered, and steps the music player. Reading the flag clears it, so the console's interrupt does not fire in a LIMI 0 section.  Call only between VDP transfers.  Uses R0-R8, R12.

### `KPFR`

a frame has passed during a long byte loop (the caller read the VDP status, saw bit 7 and thereby cleared it): poll the keyboard, every register but R0 kept.  Use it inside tight loops that cannot afford KIDLE's own register use.

### `KWAIT`

wait for a key: R0 = its code (high byte).  Runs frames (VSYNC, KPOLL) until one arrives, so it is for modal moments only (a message that waits for a key, a prompt): the module's TICK does not run meanwhile.  Uses R0-R8, R12.

## Text on the screen (text.a99)

### `PUTS`

length-prefixed string at R1 to position R0, attribute R2. Uses R0-R7.

### `FILLA`

attribute R1 (high byte) over R2 cells from position R0.

### `FILLN`

glyph R1 (high byte) over R2 cells from position R0.  Leaves.

### `DECW`

R1 as an unsigned decimal number at R0, attribute R2, no leading zeros.  Returns R3 = the number of digits.  Uses R0-R8.

### `PUTC`

glyph R1 (high byte) at position R0 with attribute R2. Uses R0-R2, R6.

### `HEX2`

the low byte of R1 as two hex digits at R0, attribute R2. Uses R0-R7.

### `HEXD`

the low nibble of R4 as a hex digit at *R3+ (R3 moves on one). Leaf.  Uses R3, R4.

### `HEX4`

the word R1 as four hex digits at R0, attribute R2.  Uses R0-R7.

### `CLS`

clear the screen: every glyph a space and (where the mode has an attribute table) every attribute R1 (high byte; usually (RTEXT*16+RBG)*256).  Uses R0-R2.

### `BOX`

a single-line frame in glyphs 1-6 (the UI glyphs: docs/GLYPHS.md): R0 = the top-left cell's position (row * columns + column), R1 = interior width, R2 = interior height, R3 = attribute (high byte).  The interior is left alone.  Uses R0-R9.

### `BXCEL` *(internal)*

one cell; BXRUN - R2 cells: glyph R1 (high byte) from position R0, attribute R7.  Use R0-R2.

## Modules (modules.a99)

### `MODCALL`

call entry R1 (the ADDRESS of a word in a module's entry table: >C000 + 2 * the entry's number) of the module in pages R0/R0+1, then map the calling module back.  R0 returns from the call; the other registers are whatever the called routine left, so pass arguments in R2-R9 or in memory.  Calls nest.  A module may not call another's routines directly (they are not mapped): use this.  The .callmod macro (macros.a99) loads R0 and R1 for you.  Uses everything the called routine does.

### `GOMOD`

switch to the module whose first page is R0, handing it R1 as its argument.  Takes effect when the calling TICK returns to the main loop (so the caller finishes its work first, and may still be running in slot C when it calls this).  The target's INIT is called with R0 = the caller's first page and R1 = the argument; PREVPG holds the caller's page afterwards, so a module can go "back" with GOMOD PREVPG. Leaf.  Uses nothing.

## The page pool (pool.a99)

### `PINIT`

the pool manages pages R0 up to (not including) R1; all free. Pages outside the range are never handed out.  Uses R0-R6.  Leaf.

### `PSET` *(internal)*

mark page R0 free in the bitmap.  Leaf (R11 is kept in R3). Uses R2, R3, R4, R5.

### `PBIT` *(internal)*

R2 = the address of page R0's bitmap byte, R4 = its mask (in the high byte).  Leaf.  Uses R2, R4, R5.

### `PALLOC`

the lowest free page: R0 = its number, or 0 if the pool is empty.  The page is marked in use.  Uses R0-R5.  Leaf.

### `PRELS`

give page R0 back to the pool (it must have come from it). Releasing a page twice is harmless.  Uses R0-R5.  Leaf.

## Files (files.a99)

### `FSEL`

choose the file handle (0-2) the other file routines act on: R0 = the handle.  R0 = 0, or >FF if there is no such handle (and the choice stays). Each handle's file stays open while you use the others.  Leaf.  Uses R0.

### `FPADR` *(internal)*

R0 = the VRAM address of the selected handle's PAB.  Leaf.

### `FOPEN`

open the file named by R2 (a length-prefixed string). R0 = flags in the high byte (add FIN/FOUT/FUPDT/FAPP, FVAR/FFIXED, FINTL/FDISP: FIN+FVAR is >1400, a DIS/VAR file for input), R1 = the record length (0 lets an input file say it; for fixed files the length they were made with). R0 = 0 or the error.  A name that is only a device and dot ("DSK1.") opens the disk's catalog: FIN+FINTL+FFIXED with record length 38 (see FCNUM).  Uses R0-R9 and the DSR's.

### `FREAD`

read the next record into the buffer at R1 (up to 255 bytes). R0 = 0, 5 at the end of the file, or the error; R2 = the record's length (also in FLEN).  Uses R0-R9.

### `FWRITE`

write R2 bytes (0-255) from the buffer at R1 as a record. R0 = 0 or the error.  Uses R0-R9.

### `FCLOSE`

close the file.  R0 = 0 or the error.  Uses R0-R9.

### `FDELETE`

delete the file named by R2 (DSR opcode 7).  R0 = 0 or the error.  Uses R0-R9.

### `FCALL`

call the DSR for the PAB at FPABV: the previous error cleared, the scratchpad it uses kept and put back, >8356 at the name length. R0 = 0, the error, or >FF.  Uses R0-R9.

### `FCNUM`

number n of a catalog record: R1 = the record's address (as FREAD left it after opening "DSK1." as FIN+FINTL, record length 38), R2 = n.  R0 = the integer.  Record 0 is the disk (name, 0, its size in sectors, sectors free); every other record is a file (name, type, size in sectors, record length; a type is 1 DIS/FIX, 2 DIS/VAR, 3 INT/FIX, 4 INT/VAR, 5 program, negative for a protected file) and an empty name ends the catalog.  Numbers are 8-byte radix-100 floats after the name; this reads small integers only (under 10,000), as catalogs hold.  The name is the length-prefixed string at the record's start.  Uses R0-R5. Leaf. R2:R3 = n * 9 (each number is a length byte and 8 bytes)

### `DSRLNK`

find the device named in the PAB and call its DSR (from The Lantern Coast).  >8356 -> the PAB's name length byte.  R0 = 0, the DSR's error 1-7, or >FF (no card has that device).  The console's own DSRLNK is not used: it needs the GPL environment the kernel does not keep.

### `DLGPL` *(internal)*

(entered after LWPI GPLWS, so R9 R12 R13 R15 here are the GPL workspace's) call the DSR entry in FDENT as the console's GPL would: R12 = the ROM's CRU base, R13 = >9800 (GROM read), R15 = >8C02 (VDP address).  The DSR returns to R11+2 when it handled the call, R11 if not.

## Music and sound (music.a99)

### `MUPLAY`

start the song whose first SAMS page is R0 (the song's pages must be consecutive).  Any song playing is replaced.  R0 = 0 if it began, 1 if the pages do not hold a song.  Uses R0-R5, R12.

### `MUSTOP`

stop the song and silence the chip.  Leaf.  Uses R0.

### `SNDOFF`

silence all four voices (attenuation 15), song or no song. Leaf.  Uses R0.

### `MUPAUSE`

R0 = 1 pause the song (the chip goes quiet), R0 = 0 resume it (the chip is put back as the song had it).  Does nothing if no song is playing.  Uses R0-R2, R11 is kept.

### `MUTICK`

advance the song one frame.  The main loop calls it every frame; call it yourself only if you run your own frame loop.  Uses R0-R8, R12 (and slot B is left as found).

### `SNDTONE`

set a tone voice directly (sound effects, or music of your own). R0 = the voice 0-2, R1 = the divider 1-1023 (frequency = 111,861 / divider Hz), R2 = the attenuation 0-15 (0 loudest, 15 off).  While a song plays its voices would overwrite yours: use a voice the song does not.  Leaf. Uses R0-R4.
